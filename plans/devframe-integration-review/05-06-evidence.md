## Current implementation

The `@histoire/devframe` package exposes `./client`, `./node`, `./host` and `./report` entries. Importing the client or Node factories does not start a listener or connect a session. The host explicitly installs the Devframe definition, provides its own authenticated connection, and optionally mounts the fetch-shaped MCP handler. The existing isolated MCP endpoint is not modified by the adapter.

Browser and agent identities come from separate host-provided authentication callbacks. Browser peer IDs, origins, discovery records and caller-supplied JSON are not credentials. Pairing grants are high-entropy, hashed at rest, one-use, time-limited and bound to principal, canonical source, scopes and the host authority revision. Host callbacks verify the claimed source/document and authorize each discovery and finite call. The broker checks host authority across asynchronous boundaries and requires the host to increment `authorityVersion()` and synchronously call `bridge.invalidate()` for affected attachments when policy, source or runtime ownership changes. Without this host contract, revocation is not guaranteed.

Attachments use targeted Devframe RPC, bounded work, per-operation cancellation, lease expiry, exact peer ownership and identity-checked cleanup. The host must connect `onPeerDisconnect` to `bridge.onPeerDisconnect(meta)`. The adapter closes its own registrations, observations and handler; it does not close caller-owned sessions, connections or HTTP servers. A cross-origin browser host also needs an explicit Devframe origin allowlist and a host CORS policy allowing its origin to fetch `__connection.json`. The successful browser fixture used a narrowly scoped metadata CORS response.

Finite services include authorized live inspection, attributed component event history and diagnostics. Events and diagnostics have separate grants. Events-only access does not start console observation. Event cursors carry an attachment-local opaque lifetime, rotate on observed clear/reset, and fail explicitly when an earlier lifetime is requested. Session-wide event loss counters are reported without claiming that every missing sequence belonged to the selected target. Diagnostics use the SDK's explicit shared observation and stop it on attachment retirement. A separately granted highlight action supports selectors; component-ID highlight remains unavailable.

## Executed evidence

- On Node 24.22.1, strict TypeScript checking passed against isolated copies of current adapter, protocol and SDK sources. The final serial adapter suite passed 37 tests across 11 files against rebuilt packages, including real-browser and local transport tests, report tests, host tests and the scope-bypass regression. Adapter-local unit/transport tests use controlled SDK substitutes; the mounted-browser gate uses the real SDK and runtime.
- Real Devframe 1.2.2 WebSocket tests covered two authenticated peers, a denied third peer attempting to redeem a valid grant, principal isolation, exact peer routing, cancellation reaching the SDK substitute, explicit detach, surviving peer, repeated lease expiry and re-pairing, and caller HTTP server survival. Event-only scope passed through WebSocket and MCP without accessing `session.debug`; two individually valid 35 KiB events appeared on successive pages without cursor loss.
- Real MCP client tests covered authenticated resource discovery, denied principal, structured error, cancellation reaching a peer over TCP HTTP, endpoint shutdown during held authentication, observation-loss errors instead of empty diagnostics, and host server survival. Node disposal joins bounded retirement acknowledgements; tests cover reentrant disposal, failed and timed-out acknowledgements, and unconfirmed SDK diagnostic cleanup without closing the caller server or connection. The principal and document policy were fixture-owned callbacks.
- Authority tests held authorization, verification and replies while cancelling, disconnecting, withdrawing discovery or changing the host revision. They cover prompt invalidation and unrelated-peer survival. A private mutation removing caller abort propagation made the held-authorization assertion fail. An explicit service-to-kind regression first demonstrated a scope bypass and now rejects forged inspection/component kinds before any peer invocation.
- With serially built packages, two separately built Histoire project roots and URLs ran in separate Chromium browser contexts, with independent authenticated Devframe and MCP principals. Alice clicked her actual mounted story, yielding unsaved count `4` and an actual component event; Bob's separate project stayed at count `3`. MCP resource discovery exposed only each principal's attachment, and Bob's attempt to inspect Alice's attachment was denied. Alice's live event history, component tree/details, diagnostics and axe findings were read through Devframe WebSocket and MCP TCP; selector highlight acknowledged the owning runtime without changing selection. Alice had one mounted canvas.
- In the same real-browser gate, Bob's post-runtime origin-policy HTTP response was held. Advancing the trusted host authority revision and invalidating only Bob's attachment settled his MCP request as an error within one second; Alice still read her unsaved count. Separately, after successful diagnostic observation, the test served a malformed static origin-policy response to Alice's real SDK poll. The poll request was observed, the story runtime remained ready, and the diagnostic MCP call returned structured `SESSION_UNAVAILABLE` instead of an empty success. These are controlled HTTP policy faults, not a proof of preempting synchronous runtime projection.
- Historical Devframe 1.2.2 and agentic 1.2.2 compatibility probes were rerun in a temporary directory with real local transport. Generic agentic MCP projection lacked principal and cancellation context and did not preserve returned raw `isError`; this adapter uses the explicit MCP SDK server 2.3.1 seam instead. MCP Node adapter 2.1.0 and client 2.3.1 were used by tests.

## Remaining gates and limits

- The manifest is configured for public access; no package was published. Packed-consumer exports and browser bundle graph, Node16/NodeNext/Bundler declarations, full workspace checks, and final compatibility documentation remain slice 09 work.
- The mounted-browser gate covers two concurrent projects and principals, a held policy response during targeted revocation, and one diagnostic poll failure. It does not prove reconnect/reused peer IDs in this adapter path, every policy or socket failure timing, or cancellation of synchronous projection already executing.
- Real story event proof covers one event. Overflow, clear/lifetime rotation, byte limits and pagination are covered by adapter tests, not by an actual story producing 1,000 events.
- Diagnostic text is document-wide observation, not causal attribution to the selected component. SDK redaction targets common credential patterns and cannot guarantee removal of arbitrary unlabelled secrets.
- Devframe 1.2.2 birpc uses a 60-second default timeout for unanswered RPCs. The adapter limits unresolved operation calls to 64 and unresolved retirement calls to 64 per bridge until upstream settlement; browser pairing retains at most 32 unresolved attempts per connection, including a 60-second retention after client-wrapper timeout; targeted cancellation uses one-way events. Bounded disposal does not claim that birpc internals are immediately released or close a caller-owned socket.
- Explicit host configuration is essential: the adapter cannot verify an identity or source unless the host callbacks do so, and it cannot infer authority changes without revision/invalidation notifications. No automatic Devframe MCP/shared-state projection is enabled by this package.
- Component trees, accessibility and selector highlight are exposed under separate authorized scopes. Component-ID highlight remains unavailable. Final review, old MCP regression suites and any CI/deployment evidence must be reported separately.
