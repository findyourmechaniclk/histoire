# Live inspection evidence

**Later update:** Vue component-ID highlighting is implemented with a separately advertised capability and exact owner-bound leases. It supports only a single provable in-root rendered element; ambiguous, teleported, stale and truncated targets fail closed. Chromium exercised component selection, geometry changes, unmount and Vue Transition retirement. Earlier notes below describing component-ID highlighting as unavailable are superseded.

Focused provider/runtime/capability suites passed 17 tests; the real Chromium Vue inspection gate passed 4 tests, with a separate Transition regression failing before the ownership fix and passing afterward. Active component ownership is rechecked at most every 100 ms, with limits of 500 instances, depth 20 and 10,000 VNodes. A failed recheck clears only its own lease.

## Implemented and validated

- `session.inspect.variant()`, `dom()`, `components()`, `component()`, `componentForElement()`, `accessibility()`, `pick()` and selector-based highlight operations address the existing primary runtime, capture exact target and document ownership, validate bounded input and result, and never select or mount a target. Component-ID highlight remains unavailable.
- Bridge cancellation forwards the initiating request ID and captured owner. SDK operations reject late success and failure after source, selection, runtime, mount or session retirement. Live results are detached and immutable.
- Inspection capability requires source opt-in and an authenticated ready actor capability. Component capabilities require an actual unique provider registration for that actor. Capability withdrawal, retirement and HMR revoke the actor projection. Cross-origin use checks both current effective embed origins and inspection origins, including a refreshed static deployment override at admission and completion. Same-origin access still requires capability opt-in.
- Real Chromium with built packages passed four live inspection scenarios: unsaved state and DOM through same-origin and allowed cross-origin hosts, denial for a host allowed to embed but not inspect, two concurrent sessions with distinct targets, disposal of one without affecting the other, and a fresh isolated Node read returning initial rather than unsaved state. Unmount rejects subsequent reads.
- A separate real Chromium scenario holds the second external origin-policy HTTP response after the runtime has produced its result. Caller cancellation, selection change away and back, physical source-bridge disconnect followed by reconnect of the same session, and session disposal/replacement each reject the old request; a new inspection succeeds. The held dependency is HTTP interception, so this does not establish cancellation of synchronous projection while it runs.
- A real dev-server HMR scenario holds the browser's scanner module response during a live audit, changes the story file, and waits for a new source revision and runtime document. The old request rejects with `STALE_REVISION`; releasing the old response cannot revive it, and a fresh audit succeeds. The hold precedes scanner execution.
- Real Chromium Vue coverage verifies opt-out, exact component ownership and props, stale component ID rejection after changing target, and same-target HMR replacement. Highlight coverage verifies successor overlay survival after predecessor timeout, eventual cleanup, unchanged focus, and pointer interaction. Highlight is a translucent non-interactive background, with no colored border.
- Chromium picking resolves a point in the exact story document to a selector that reads the expected element; an outside-viewport point is unmatched. A leased highlight can be cleared only by its captured owner and lease ID: stale clear preserves the successor, current clear succeeds once. A real DOM test also rejects a different connection's clear.
- Live accessibility Chromium coverage verifies separate opt-in, locally bundled axe version and an `image-alt` finding scoped to the selected story, absent and invalid selectors, and unchanged selection. The result is an automated audit, not a compliance certification.
- SDK suite: 32 files, 152 tests passed with Node 24 and escalation for its subprocess test. Focused embed policy/local-port tests passed 6 tests. Existing MCP inspection browser-service test passed 12 tests. A targeted bridge cancellation test proves exact request ID and owner reach the remote abort signal; this uses the existing port fixture, not a browser.

## Open proof and implementation boundaries

- Runtime projection is synchronous; cancellation while projection is actively executing is not demonstrated. The HMR gate holds scanner module delivery, while the reconnect gate holds an external origin-policy response after projection; neither claims to preempt synchronous work.
- SDK primary currently addresses an already-ready target in its own runtime document. It does not identify independent nonselected workbench canvas frame sessions. A host-owned exact-frame service seam remains necessary.
- Selector highlight successor timeout is covered. A browser regression demonstrated that an overlay persisted when origin permission was withdrawn after installation but before the reply; after the exact-request cancellation fix, Chromium confirms removal and a subsequent authorized highlight succeeds. Component-ID highlight remains unavailable. Live audit cancellation through an actively held scanner remains a separate proof boundary.
- Each current preview runtime renders one keyed actor. Grid, List and Matrix peers use separately owned sessions and documents; changing one session's selection replaces that actor. A real Chromium held explicit read survived a selection change in the other session. A single-session, same-document multi-actor case is not available in the current topology.
- Browser evidence is local Chromium only. It is not a claim about other browsers, production deployment or external provider interoperability.
